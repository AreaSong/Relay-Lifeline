# 架构说明

[English](architecture.md)

Relay-Lifeline 将请求数据面与管理控制面分离。

```text
AI 客户端 -> 数据面 -> OpenAI-compatible 中转站 -> 模型提供商
                │
                ├-> 状态注册表 -> 持久化请求时间线
                │                    │
                ├-> 风险引擎 -------┴-> 管理 API <- Web UI
                │
                ├-> 监控存储 -------┘        │
                │   1,440 个 UTC 分钟桶      │
                │   + 有界事件环             │
                ├-> 有界通知队列 -> Webhook
                ├-> 结构化运行日志 -> 管理 API
                └-> 临时捕获 -> 加密持久存储
```

## 数据面

网关读取并限制下游请求体，然后为每次尝试重新构建上游 HTTP 请求。Authorization 和协议 Header 会被透传，但不会被记录。客户端取消会传播到当前上游调用、队列等待、暂停等待和重试计时器。

每个上游响应先缓存在内存中，超过配置阈值后转存到权限为 `0600` 的临时文件。只有协议校验成功后才向客户端交付，因此网关可以在半截模型输出暴露之前判断是否需要重试。

在 `all-errors` 模式下，传输故障、所有非 2xx、响应头超时、正文空闲超时、无效或失败 JSON、失败或不完整 SSE、缺失完成标记都可重试。正文空闲计时器在每次收到数据后重置，防止已收到响应头的连接永久停顿。等待时间在配置的最小值和最大值之间选择，也可被 `Retry-After` 延长。全局恢复门控制多个恢复请求的启动间隔。

为了在等待期间发送保活，网关会提前把下游 HTTP 状态提交为 `200`，因此最终失败通过响应体中的 OpenAI 风格错误信封表达。流式请求收到 SSE 注释保活；非流式 JSON 收到空白字符，仍符合 JSON framing。

## 控制面

管理 API 使用分层 Bearer 密钥。Viewer 只能读取脱敏状态、历史、时间线、指标、日志和过滤捕获；Operator 增加暂停/恢复、立即重试、取消、捕获控制和配置写入；Sensitive Data 再增加完整原文下载。

运行记录保存稳定消息代码和插值详情，面向人的文字在 API 响应时翻译，所以同一条已完成历史可以切换中英文查看。请求与事故时间线从经过校验的 SHA-256 哈希链日志恢复；启动时把未完成请求标记为 `orphaned`，不会自动重放。保留期维护按完整实体清理过期记录，并通过 `0600` 临时文件、`fsync` 与 rename 原子重建保留链。

配置写入会校验完整的带版本文档，并在支持时通过原子 rename 保存。Docker 单文件绑定挂载会回退到有界原地写入。持久化前，当前配置会以 `0600` 权限复制到最多保留十份的备份集合；独立预检接口可在不修改状态的前提下返回权威的热更新和需重启区段。依赖服务构造或 HTTP Transport 的字段返回 `restartRequired`；策略和语言字段在运行期间从当前 Store 读取。

控制面契约提供明确的 API 版本响应 Header 和运行元数据接口，因此无需进入容器即可查看构建版本、revision、构建时间、镜像引用、进程启动时间、Go 平台、管理 API 版本和配置 schema 版本。

运行元数据同时包含当前进程命名空间内的 PID、父 PID、Go 协程、GOMAXPROCS 和 Go 内存快照。它不会尝试通过挂载宿主机 `/proc` 或 Docker socket 获取宿主机进程表。客户端可以通过有界白名单 Header 声明客户端和任务 ID；标识会在进入时间线前完成格式校验，并在转发上游前移除。Codex app-server 的 `threadId` 是逻辑会话标识，后台终端 `processId` 是 app-server 层的进程标识（另有可能为空的 `osPid`），两者都不等同于宿主机操作系统 PID。该信息只用于关联，不构成身份认证。

收到退出信号后，Readiness 立即切换为 draining，等待中的请求会获得一次立即重试机会，主进程同步等待 HTTP Handler 排空到配置的关闭期限。强制终止无法跨进程保留下游 TCP 连接；未完成捕获会在下次启动时标记为 `interrupted`。

## 内存监控

监控使用 1,440 个 UTC 分钟桶，最多提供当前进程 24 小时的数据。分钟桶记录请求、尝试计数和每分钟负载峰值；当前 active、queued、waiting、requesting 负载另行维护。恢复耗时与尝试次数使用固定直方图，另有独立的 1,000 条事件环支持游标续读。所有监控状态在重启后清空；窗口尚未收集完整时会明确标记，不会用零值伪装成完整历史。

## 安全可观测性

错误详情提取器只接受已知 JSON/SSE 字段和白名单响应 Header，随后遮蔽 Bearer Token、密钥形态值和 URL 凭据，并限制总长度。无法解析的原始正文不会存储。诊断导出会再次显式移除错误详情。

监控指标不包含 Prompt、响应正文、Authorization、Header 或原始错误。错误分布只允许稳定的 `transport`、`protocol`、`auth`、`rate_limit`、`client`、`server`、`http` 分类。运行事件只包含稳定代码以及请求 ID、分类、状态码、attempt 和管理结果等有界字段。

风险引擎只发出去重提醒，不改变重试策略。通知使用独立有界队列和投递重试，Webhook 故障不会阻塞模型流量。

日志和 Webhook 同时包含稳定英文事件标识和本地化文字，其语言独立于 UI/API 语言。

实时运行日志位于容量和时间均可配置的内存环形存储中，只记录事件、请求 ID、尝试次数、状态码和安全字段，不保存正文。日志查询使用有界尾页或游标分页，并显式报告保留期或容量覆盖造成的缺口。该日志环与游标 API 使用的固定 1,000 条监控事件环相互独立。单请求时间线超出 100 条时保留首事件与最新事件并报告丢弃数量。临时诊断捕获由管理员显式激活，只领取接下来有限数量的请求，并在激活窗口结束后自动关闭。

捕获正文按 1MiB 数据块使用 AES-256-GCM 认证加密。每条捕获生成独立数据密钥，再由活动 Key ID 对应的主密钥包装。Key Ring 保留仍被历史记录引用的旧主密钥；轮换只重包裹数据密钥并原子更新元数据，不重新加密大正文。认证 Header 在写入前删除；过滤预览在解密后进行结构化遮蔽；完整原文只通过 Sensitive Data 鉴权和明确确认后的流式 ZIP 下载。容量不足只关闭正文捕获，不改变代理、重试或响应交付。

## Web UI 韧性

Signal Continuity 场景按需加载本地 Three.js 包，展示既有网关状态，不产生额外探针流量。页面进入后台时暂停动画，遵循系统“减少动态效果”设置，在移动端降低渲染密度；WebGL 初始化失败或 Context 丢失时以静态 DOM 拓扑替代 Canvas。ECharts 运行图表同样按需加载。同步启动脚本会在 React 启动前应用 `system`、`light` 或 `dark`，避免主题闪烁。

## 诊断

诊断检查本地配置、配置文件访问、管理密钥长度、缓存权限、磁盘容量和唯一配置上游的 DNS/TCP 连通性，不发送 HTTP 模型请求。导出的配置会移除 URL 用户信息、Query、Fragment 和完整 Webhook 地址；诊断包附带近期结构化日志和一小时监控摘要，但不包含正文或安全错误详情。

## 职责边界

Relay-Lifeline 只维护一个上游目标。账号池、多供应商路由、模型映射、渠道权重和多个中转站之间的故障切换属于 CPA 或其他上游中转站。

## 完成规则

- Responses API：必须出现 `response.completed`。
- Chat Completions 流：必须出现 `[DONE]`。
- `response.failed`、`response.incomplete`、错误信封、非 2xx、传输失败或截断流都视为失败。
- 非流式 JSON 必须可解析，且不能包含顶层 failed、incomplete 或 error 状态。

## 已知限制

上游调用已经计费但完成标记在传输中丢失时，重试可能造成重复工作或费用。只有上游支持的幂等机制才能彻底处理该情况。
